# 보안 정책 (AI 작업 원칙)

이 문서는 AI Agent가 GETI-Client에서 작업할 때 지켜야 하는 보안 원칙을 다룬다. 실제 인증/인가 구현은 이 단계의 범위가 아니며, 여기서는 AI 작업 과정 자체의 보안 원칙과 프론트엔드 특유의 노출 위험을 다룬다.

## Secret 관리

- Secret, Token, API Key, Password, 인증서, Private Key를 코드나 설정 파일에 하드코딩하지 않는다.
- 예시나 문서에도 실제로 동작 가능한 Secret 값을 사용하지 않는다. 필요하면 `YOUR_SECRET`, `<token>`처럼 명백한 placeholder를 사용한다.
- `.env`, 인증서(`*.pem`, `*.key`, `*.p12`), 기타 Secret 파일을 Commit하지 않는다. `.gitignore`에 이미 등록된 항목을 임의로 제거하지 않는다.
- 새로운 종류의 로컬 전용/Secret 파일이 생기면 `.gitignore`에 추가할지 먼저 검토한다.

## 브라우저 노출 (프론트엔드 특유의 위험)

프론트엔드 코드는 최종적으로 사용자 브라우저로 전달된다. 서버에서만 보이는 값이라는 가정을 하지 않는다.

- **`NEXT_PUBLIC_` 접두사가 붙은 환경변수는 빌드 시점에 클라이언트 번들에 그대로 박힌다.** Secret, Private Key, 관리자 Token을 절대 넣지 않는다. 공개돼도 무해한 값(공개 API baseURL, 공개 분석 ID)만 넣는다.
- 접두사가 없는 환경변수는 서버 측(Server Component, Route Handler, Server Action)에서만 접근 가능하다. 이 값을 Client Component로 props로 넘기면 브라우저에 노출된다.
- 서버에서 가져온 데이터를 Client Component로 넘길 때 필요한 필드만 넘긴다. 사용자 객체 전체를 넘겨 비밀번호 해시나 내부 식별자를 노출하지 않는다.
- 권한 검사를 클라이언트에만 두지 않는다. 화면에서 버튼을 숨기는 것은 UI 편의이며 보안이 아니다. 실제 권한 검사는 서버에 있어야 한다.
- `dangerouslySetInnerHTML`을 사용하지 않는다. 외부에서 온 HTML을 렌더링해야 하는 요구사항이 있으면 임의로 구현하지 않고 사용자에게 확인한다.
- Token을 `localStorage`에 저장하는 방식을 임의로 도입하지 않는다. 인증 방식은 백엔드와 합의된 별도 Issue에서 결정한다.

## 로그와 출력

- 로그, 커밋 메시지, PR 본문, 완료 보고에 Secret이나 개인정보(실제 사용자 이메일, 전화번호 등)를 출력하지 않는다.
- Secret이 포함되어 있을 가능성이 있는 파일(`.env`, 인증서 등)의 전체 내용을 읽어서 대화에 그대로 출력하지 않는다.
- API 응답을 `console.log`로 찍어두고 그대로 Commit하지 않는다. 브라우저 콘솔에 사용자 데이터가 노출된다.

## 인증과 인가

- 테스트나 개발 편의를 위해 인증/인가 로직을 임의로 제거하거나 우회하지 않는다.
- 인증/인가가 아직 구현되지 않은 현재 단계에서, 임시로 우회 코드를 추가하고 완료된 것처럼 남겨두지 않는다.

## 외부 입력과 Dependency

- 사용자 입력이나 외부 데이터를 다루는 코드를 작성할 때는 검증 없이 신뢰하지 않는다.
- 외부에서 받은 URL을 그대로 `href`나 리다이렉트에 사용하지 않는다.
- 새 Dependency를 추가하기 전에 출처와 필요성을 확인한다. 근거 없이 여러 Dependency를 한 번에 대량으로 추가하지 않는다. npm 생태계는 이름이 비슷한 악성 패키지가 존재하므로 패키지명을 정확히 확인한다.
- 검증되지 않은 외부 Script를 다운로드해서 실행하지 않는다. `curl | sh` 형태를 사용하지 않는다.
- 외부 CDN에서 스크립트를 직접 불러오지 않는다.

## Shell 및 Git 명령

- 파일을 삭제하거나 되돌리는 명령을 실행하기 전에 영향 범위를 확인한다.
- [`AGENTS.md`](../../AGENTS.md)에 명시된 파괴적 명령(`git reset --hard`, `git clean -fd`, `git push --force`, `rm -rf` 등)은 사용자의 명시적 요청 없이 실행하지 않는다. 일부는 `.claude/settings.json`의 `deny`로 차단되어 있으며, 우회 명령을 만들어 실행하지 않는다.
- Shell Injection이 발생할 수 있는 방식으로 외부 입력을 명령어에 그대로 삽입하지 않는다.

## 운영 데이터와 사용자 데이터

- 운영 환경의 API나 데이터베이스에 직접 접근하거나 수정하지 않는다. 개발 중 API 호출은 개발 환경 또는 Mock을 사용한다.
- 테스트 데이터로 실제 사용자 정보를 사용하지 않는다. 필요하면 명백히 가짜임을 알 수 있는 값을 사용한다.

## 보고 원칙

- 보안과 관련된 가정(예: "이 값은 아직 실제 Secret 관리 체계가 없어 평문으로 두었다")을 발견하면 임의로 판단해 조용히 넘어가지 않고 완료 보고에 명시한다.
- 작업 범위 밖에서 보안 문제를 발견하면 임의로 수정하지 않고 후속 Issue 후보로 보고한다.
